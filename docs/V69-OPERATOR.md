# Windows Proxy Doctor · 固定出口异常时怎么办

**给 Agent 的一句话**　“只读检查 Windows 现在选择的代理、首跳、核心监听和显式 HTTPS 出口。告诉我哪些应用路径仍未知。若有未完成修复，先报告它，等我选择。”

## 从只读检查开始

从候选仓库根目录，在 Windows PowerShell 中运行下面的命令。配置目录选用当前部署所用的目录。脚本在前台采样三次后退出。

```powershell
$config = Read-Host '现有 proxy_v4 配置目录的完整路径'
powershell.exe -NoProfile -File .\proxy_v4\state-v4.ps1 -ConfigDirectory $config -Samples 3 -IntervalSeconds 5
```

出现 `PAUSE_APPLICATIONS` 时，先停止依赖固定出口的应用活动，记下时间和原始告警。网页和桌面程序需要分别核对。前台诊断会进行显式 HTTPS 探测，退出诊断后不会代替应用阻断网络。告警不是阻断。

只读分类不修改系统。在候选仓库根目录运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\proxy_v6\tests\repro\V69Lifecycle.ps1`。`USER_OFF` 表示用户关闭了代理，不要把它恢复。`ALIGNED` 只说明监听和系统选择一致，不证明应用已经走通。自然语言“检查我的代理为什么没有正常工作”走 Windows Proxy Doctor 的 Diagnose，再调用 `Get-ProxyDoctorFaultClass`。

| 观察 | 下一步 |
|---|---|
| 首跳 TCP 不通或 CONNECT 失败 | 看首跳客户端是否自行停止或由用户主动关闭。恢复加速后再测核心与出口。 |
| 首跳恢复，核心监听或完整链路仍失败 | 核对核心的进程映像、监听和应用实际连接。仅在确认问题范围并获授权后考虑重开客户端，再用实际应用复测。 |
| 正常切换首跳节点，应用仍工作 | 记录切换前后样本。保持现有进程。 |
| 显式链路可用，Windows 代理与保存意图不同 | 查明是否有人主动关闭、改选或启用了 PAC。只有启用中且确实漂移到已知首跳、并明确授权恢复原目标时，才考虑候选单次修复。 |
| 出口不符、探测超时、供应商不可达 | 保持应用暂停。核对固定出口服务及普通测试端点。供应商故障的归因需要独立证据。 |
| 报告未完成或无法读取的修复记录 | 保留现场。完整记录支持明确选择保留当前设置或恢复先前目标。记录损坏或权限异常需本机人工复核。 |

## 候选修复与人工选择

以下写操作供完成部署授权后使用。执行目录应为装有对应配置的同一版本。单独检出的候选可以用上文的只读入口访问生产配置；不要把生产凭据复制到源码仓库。

| 已确认的意图 | 候选入口 | 完成证据 |
|---|---|---|
| 一次性修复启用中的已知代理目标漂移 | `apply-v4.ps1 -Repair` | 写前、写后读取实际设置并采样预期 IPv4 HTTPS 出口；应用仍需复验。 |
| 中断后保留用户现在的选择 | `apply-v4.ps1 -ResolveRepair KeepCurrent` | 核销本次修复记录。此选择不会证明链路健康。 |
| 中断后明确要求回到此前代理目标 | `apply-v4.ps1 -ResolveRepair RestorePrevious` | 检查当前配置与记录相容，复读恢复的目标。如果用户已关闭或另选代理，先保留该意图。 |

看到退出码 33（已有操作）、34（未完成或不安全的事务）或 40（无法确认恢复）时停止。勿循环调用写入口。保存私有诊断记录，优先比较两次快照。诊断结果中可能含用户网络地址。

## 部署与回退门

1. 在可丢弃 Windows 环境重放目标故障。记录实际进程、目标地址族、协议、发起端错误和接收端计数。已运行连接、新连接及后台请求分开核对。
2. 向用户说明具体变更、受影响的应用、国内网站和局域网的预期可用性。全机出站阻断会同时影响这些连接。本候选的实验与诊断不需要修改宿主防火墙。
3. 取得具体部署授权后，先备份原版四个脚本及哈希、配置与 ACL，确认没有进行中的事务，准备本地离线回退副本。将候选四个脚本作为同一版本替换。避免混用两个版本的写入口。
4. 复测国内和国际 HTTPS、系统实际选择、首跳及核心、授权范围内真实应用的出口。逐项核对 IPv6、UDP、DNS、WebRTC。任何必需路径未知或失配时保持应用暂停。
5. 需要回退时，先用产生记录的候选处理未完成事务，确认用户现在的代理意图，然后成组恢复旧版脚本、验证哈希。如确实改过运行配置，仅恢复相应备份并复核配置、ACL、代理目标与正常访问。记录或回退无法验证时停止写入。真实生产部署和回退仍待授权。
