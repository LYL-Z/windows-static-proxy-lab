# CAB 集成候选验收

候选包含 V6.9 Engine、Windows Proxy Doctor Desktop、CLI 和 MIT 授权的 Skill。普通用户可先用 Skill 说明网络症状。Desktop 提供只读检查和隔离回滚演示，CLI 可输出结构化证据。

## 八项要求

| # | 状态 | 当前证据和缺口 |
| --- | --- | --- |
| 1 失败关闭 | PARTIAL | 隔离浏览器在显式代理中断后，旧请求中断、新请求失败，接收端无直连。Windows Job 四个场景覆盖它创建的测试进程。整机持久阻断和生产故障覆盖待验。 |
| 2 站点数据 | PARTIAL | 临时 Chrome 中清除指定来源的合成 Cookie 和 localStorage，对照来源保留。真实资料、权限、缓存与遗留 Flash 分别处理。 |
| 3 DNS | PARTIAL | 显式 DNS、否定应答、代理侧解析与受控 DoH 缓存可由收发双方核对。系统默认解析器和 Chrome 内建 DoH 的实际路径未测。 |
| 4 IPv6 | PARTIAL | IPv6 TCP 回环返回 Winsock 10013，UDP 超时且接收端零到达。公网 IPv6 路径和实际拦截归属待验。 |
| 5 WebRTC | PARTIAL | 临时 Chrome 默认样本有 STUN 与 UDP 数据通道。限制实验收集完成但候选和 STUN 接收均为零，TURN、视频通话和日常资料待验。 |
| 6 持续观察 | PARTIAL | 桌面分别记录本地状态、上游 HTTPS 和手动协议证据，显示过期、暂停和恢复。20 秒本地、90 秒上游采样加网络地址事件，仍会漏掉采样间的变化。 |
| 7 实际应用路径 | PARTIAL | 只读检查与中性端点 HTTPS 提供路径样本。生产应用故障期间的出口、同一出口的独立备用线路与服务资格均未验收。 |
| 8 故障恢复 | PARTIAL | 隔离回滚按哈希验证，恢复契约要求事务退出码 32 与原始写入记录。准备阶段先登记再停本地代理客户端，进程中断后可以检查记录并明确选择。StarSky 自停根因与官方重连接口仍缺现场或厂商证据。 |

## 候选范围

- Desktop 自包含 Windows x64 从 `desktop/ProxyDoctor.sln` 构建，CLI 为独立可执行程序。便携和文件夹安装均以同一来源提交为准。回滚演示只加载随包两份对应哈希的 Engine 文件并在临时根下运行。
- 回归包含 Engine 114 项、独立跨进程恢复 15 项、Desktop 和 CLI 共用 Core 的 81 项、Skill 的 15 项基础、24 项向导和 21 项故障分类。Desktop 和 Skill 还对同一份 25 条恢复契约夹具进行校验。
- 两种语言拒绝证据自报的事务失败码、缺失的原始写入日志及不匹配的日志。核对当前 Windows 代理是前后两次采样。
- Windows Sandbox 配置通过静态预检。测试主机缺少 Sandbox 启动器，访客运行保留 NOT_TESTED。短期资源采样和窗口交互不构成 24 或 72 小时长稳验收。

## 安装、升级和回退

便携目录解压后运行 `Desktop/ProxyDoctor.exe`。命令行使用 `CLI/proxy-doctor.exe`。验证随包 SHA-256 后再运行。程序未签名。

文件夹升级使用独立版本目录。先在新位置验收，随后可以切回旧位置。文件夹安装器仅对指定根下的目标工作，拒绝覆盖已有文件。卸载检查清单和文件哈希，原有未安装的文件和目录由使用者保留。复制途中报错时，将新目标保留为未完成，检查文件并另用独立目录重试。

生产部署须单独授权。部署时先保存原版四脚本、配置指纹和 ACL。成组替换后复查实际代理选择、常用内外网站和明确授权的应用路径。失败时先用建立事务的同一版本处理已登记的事务。若只登记了准备阶段，核对用户当前意图后明确选择保留现状或恢复原本运行的本地客户端。然后可成组复原旧脚本并核对文件哈希。防火墙、DNS、TUN、IPv6、启动项、客户端重启、真实快照迁移或删除各需独立授权。 [V6.9 操作参考](V69-OPERATOR.md)
