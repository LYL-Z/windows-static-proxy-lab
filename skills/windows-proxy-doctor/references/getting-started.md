# 新手操作指南

## 先告诉 Agent 你想做什么

说「用 Windows Proxy Doctor 检查我的网络」。如果现在有故障，加一句遇到的现象，例如「系统显示代理开着，浏览器却连不上」。如果正在从零准备，说「帮我准备网络代理设置，我还没有相关软件」。

Agent 会先看 Windows 是否识别到客户端、已经在运行的服务以及应用可能使用的代理。检查后应说明你当前处于哪一步、什么已经确认，以及下一步是否需要你点击或授权。常见入口如下。

| 情况 | 下一步 |
| --- | --- |
| 刚开始，库存未找到相关客户端 | 了解是否真的需要客户端。检查官方软件来源和系统兼容性，用于决定是否安装。 |
| 已有一部分软件 | 对照本机安装和运行证据。先尝试现有客户端和服务，再决定是否需要补充组件。 |
| 已经配置且希望检查 | 直接诊断。核对应用当前走的路径，再选择是否发送少量探测。 |
| 出现故障 | 先保留原样和失败发生的时刻。记录受影响应用及地址，分层检查，再讨论是否恢复。 |
| 授权、注册、安装或费用卡住 | 标记正在等待的事项。可以跳过服务或拒绝改动，继续只读检查已知部分。 |

## 哪些步骤由你完成

你本人负责账号注册、身份或人机检查、付款、接受条款和在客户端本地输入凭据。软件安装和网络设置改动各自需要独立确认。当 Agent 具备桌面或浏览器工具且获授权时，可以辅助合适的操作。工具不可用时，Agent 应给出软件名、页面位置、按钮文字、点击后的预期状态，以及出错后如何回退。安装完告诉 Agent 软件名称和屏幕状态，Agent 会重新检查安装事实。

需要另外选择网络服务时，现有合法可用的服务可以继续用。你可以选择普通官方入口，也可以主动查看带利益披露的可选链接。请在实际支付前向厂商核实价格、流量、续费、退款和协议能力。 [可选服务与利益披露](providers.md)

## 什么时候算验收通过

先记录现在能够访问的网站和应用。改动后再测试相同目标和路径。如果只有工具的 HTTPS 请求通过，告诉 Agent 你自己的应用有没有通过，以便独立记录。代理端口出现代表该本地服务正在监听。重启、退出或换节点后的表现，等相关事件实际发生再记录。

故障出现时，先按已明确授权的方式恢复到上次正常状态。没有回退权限或不确定原值时，先保留现场并等用户确认。 [故障处理手册](troubleshooting.md)

## 两个客户端怎样协同

如果你选择同时用 StarSky 和 Clash Verge，先请 Agent 确认两个客户端的本地端口、原有代理开关和已经正常运作的应用路径。通常可以让 Clash Verge 管理 Windows 系统代理，让 StarSky 保留本地入口。使用已有代理服务时，在客户端本地输入你的服务信息。配置前核对当前版本是否支持所需的连接方式，端口以本机发现为准。

仅在本机已确认功能且你同意后，再通过 StarSky「软件设置 → 设置为系统代理 → 否 → 保存设置」改变由谁管理 Windows 代理。保存后确认 StarSky 仍在监听、Windows 代理仍指向预期客户端，并在日常应用中访问先前可用的网站。如果出现回归，按修改前记录的开关状态回退并复测。完整退出、重启和自动节点切换的表现需要按实际版本查验。 [现场证据与剩余限制](lifecycle-observations.md)

## 中断后继续

需要跨会话继续时，可让 Agent 在你确认的私人本地目录使用 `windows-proxy-doctor-checkpoint.json`。关闭 Agent、安装完或重启后，把该检查点位置交回 Agent。恢复时它会重新读本机状态，并把你报告的操作和实测结果分开。你可以继续已有环境的诊断，即使跳过了某项安装或服务。

## 升级、卸载与回退

关闭正在运行的向导或前台观察脚本。安装时把完整的 Skill 内层文件夹复制到客户端指定的 Skill 目录。升级前复制旧版文件夹作回退，把新版放在干净目录后让客户端重新加载一次。卸载时移除客户端加载的 Skill 文件夹，停止的前台脚本不会再运行。需要回退时换回旧文件夹，并做同一项只读检查。单独保存的私人备份和检查点可以保留，安装或移除 Skill 本身不操作代理客户端或 Windows 网络设置。
