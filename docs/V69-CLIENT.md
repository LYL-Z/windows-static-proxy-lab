# V6.9 浏览器故障实验

这个实验回答一个具体问题：当测试中继正在传输响应时退出，已经打开的 Chrome 会怎样处理这次响应和下一次请求？实验同时确认故障期间接收端仍能收到来自另一浏览器的直连请求。

## 复现

环境为 Windows、Python 3.11、`websockets` 13.x 和已安装的 Google Chrome。从仓库根目录运行以下命令。若 Chrome 安装在其他位置，可通过 `--chrome` 指定浏览器可执行文件。

```powershell
python proxy_v6/tests/repro/V69Client.py
```

测试启动两个使用临时资料目录的无界面 Chrome，分别作为受测浏览器和正对照。HTTP 接收端、转发进程和调试通道都绑定 IPv4 回环地址。中继仅向随机测试路径所在的本机接收端转发，并添加一次性标记。接收端按路径记录带标记与不带标记的次数。两个浏览器的临时资料在退出后清除。

受测 Chrome 预先指定测试中继，并对测试目的地取消 Chromium 默认的回环绕过。正对照保留默认回环行为。此项设置仅适用于这两个临时浏览器进程。观察进程只检查中继能否到达接收端，随后测试主动结束该观察进程。[Chromium 代理与回环规则](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md)

## 读懂结果

| 场景 | 浏览器证据 | 独立接收端证据 |
| --- | --- | --- |
| 正常、观察进程退出、上游恢复 | 同一页面 `fetch` 收到 200 和预期正文 | 对应请求各经中继一次 |
| 上游失效，代理仍监听 | 浏览器收到合成 502 | 对应路径零次到达 |
| 活动响应期间中继进程退出 | 浏览器已读到第一个字节，后续流读取失败 | 该路径有一次中继请求，至浏览器退出为止零次直连 |
| 故障期间同一 Chrome 发出新请求 | 请求失败，独立记录 Chrome 的网络错误 | 故障路径零次到达 |
| 故障期间正对照浏览器访问同一接收端 | 200 和预期正文 | 对照请求直连一次 |
| 原端口重新启用测试中继 | 原浏览器重新取得 200 和预期正文 | 新请求经中继一次 |

成功退出码为 0。每次运行输出各场景、预期及实际结果、浏览器版本与子进程类型、观察与中继退出码，以及至浏览器退出时的最终直连计数。

本实验覆盖指定 Chrome 页面发出的 **HTTP / IPv4 TCP**。系统代理继承、其他桌面程序、HTTPS、UDP、IPv6、浏览器后台流量和操作系统级断网保护均需各自验收。实验的回环绕过设置不能直接用于日常浏览。真实 StarSky、Clash 和生产防火墙均不参与本实验。
