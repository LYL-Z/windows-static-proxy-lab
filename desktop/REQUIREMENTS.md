# 八项历史需求追踪

这些是原始需求的当前证据，不是完成率。没有一项已经作为生产保护验收。

| 需求 | 当前证据 | 状态 |
| --- | --- | --- |
| 网络失败时关闭 | 进程级作业守卫只覆盖它自己启动的进程。指定程序的防火墙实验因拒绝访问没有留下规则。 | 未验收 |
| 浏览数据清理 | 桌面程序不清理 Cookie 或站点数据。清理也不能当成设备身份重置。 | 未做 |
| DNS 路径 | 系统解析器对 example.com 有应答。这只说明解析器可用，没有证明解析路径。 | 部分观察 |
| IPv6 | 回环 TCP 曾在 connect 得到 10013，UDP 超时。过滤组件仍未知。没有全局关闭 IPv6。 | 未验收 |
| WebRTC | 这次没有启动浏览器，也没有接收端计数。 | 未测 |
| 保持上述结果 | 没有已部署的持续保护。监测是周期采样，看不到所有瞬时中断。 | 未验收 |
| Claude 桌面和网页的稳定出口 | 官方状态接口只说明服务状态，不说明账户资格。Aligned 不是应用已经走通。 | 未验收 |
| StarSky 与 Clash 易于修复 | 隔离回滚可以验证“用户关闭时不重新打开”。没有官方 StarSky 重连接口，也不把重启进程当成加速恢复。 | 隔离通过，生产未做 |

## 发布门槛

新快照在 V6.9 分支上改为当前用户 DPAPI 密封。旧的明文快照仍能恢复。过期清理只允许在测试模式和临时目录里，并且要显式确认。生产快照没有迁移或删除。

C-12 的当前分支处理是：含长凭据样式的 `proxy_diag` 文件已从分支尖端替换成说明，历史提交没有改写。私有路径和历史公网地址仍留在旧提交里。没有发现私钥块。如果那些诊断文件来自真实代理配置，应轮换对应密码；不要把旧 blob 再检出到工作目录。

这两项都不是本轮桌面提交新引入的缺陷。V6.9 工作区里已有的未跟踪证据目录没有被修改。
