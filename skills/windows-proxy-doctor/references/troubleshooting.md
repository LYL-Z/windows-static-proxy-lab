# 故障处理手册

先问用户哪个应用出错、何时开始、最近是否操作过设置。保留旧配置和故障证据。使用 `Start-ProxyDoctor.ps1 -Goal Diagnose` 和环境发现，在对应层取证。对「检查我的代理为什么没有正常工作」或同等说法，在该命令之后调用 `scripts/ProxyFaultClass.ps1` 中的 `Get-ProxyDoctorFaultClass`。它只对传入的观察分类为 `USER_OFF`、`PROXY_DRIFT`、`CORE_DOWN`、`FIRST_HOP_DOWN`、`ALIGNED` 或 `UNKNOWN`，不修改系统设置。`USER_OFF` 表示用户关闭了代理，不要建议恢复。`ALIGNED` 只表示本地选择与监听一致，不是应用访问成功。An alert or UI status is not proof the network was blocked. 下表的原因均为排查方向，验收随实际证据更新。使用与用户故障相关、获准的公开测试地址。

| 现象 | 必要检测与证据 | 可能原因 | 所需授权与恢复 | 验收 |
| --- | --- | --- | --- | --- |
| 已安装客户端无法启动 | 核对安装或便携位置、运行状态、核心就绪时间，记应用错误码与脱敏日志片段。 | 程序与系统架构不匹配、权限不足、配置无效或进程冲突。 | 默认读取。重新启动或运行获验证的安装包需获授权。逐项检查原生错误提示，再使用已验证的旧版本或已备份配置。 | 客户端和核心能运行，所需本地端口归属正确，受测应用可用。 |
| 端口被占用 | 对照软件设置的端口、绑定地址、实际监听进程和时间。 | 另一程序抢占、旧实例存活、或应用配置了不同地址。 | 默认读取归属。停止其他进程或改端口前说明影响并获授权。优先更改目标客户端原生监听选项，复核依赖程序。 | 使用目标客户端拥有的监听入口访问相同测试目标。 |
| 程序运行但没有流量 | 查 Windows 对目标的选择、应用自己的设置、请求实际路径与监听者。 | 软件正空闲、应用选择直连/其他代理、连接仍使用缓存。 | 默认查看。若用户希望修改代理选择，单独授权后使用原生界面。 | 比较真实应用、Windows 已选路径、显式监听三个证据，并记录哪层已实测。 |
| UI 和 Windows 代理不一致 | 保存意图、界面开关与 Windows 实际选择分开采样。另查 PAC、WinHTTP 和应用覆盖。 | 配置已保存但尚未生效、按连接/用户策略变化、其他程序写入。 | 默认只读。确认唯一的系统设置管理者，获授权后通过原生选项修复一处。 | 按相同应用和目标验证系统选择及路径。 |
| 客户端改变了另一个客户端的配置 | 比较变更前后样本，按需读已有事件并匹配操作、时刻和进程。无匹配事件时标记写入者 `UNKNOWN`。 | 两个程序管理同一份设置、登录任务或企业配置执行。 | 现有日志需可读。启用审计、使用需提升权限的工具或变更开关应分别获授权。优先保留单一管理者。 | 其他客户端仍监听，Windows 目标与网站访问符合预期。另测重连、退出和重启。 |
| 上游断开或重新连接 | 用前台观察器记录本地监听和第一跳，分别测试失败时与恢复后的新 HTTPS 请求。 | 远端会话失效、客户端切换节点、本地监听退出或服务异常。 | 默认只读。切节点、重启或重新认证由用户完成，或由 Agent 在获授权的范围内协助。 | 观察监听回来，再复测新请求。已打开会话及冷启动分别记录。 |
| StarSky 自停后已重新加速，Clash 仍无流量或显示非预期出口 | 先看 StarSky 本地监听、Windows 代理目标和 Clash 本地入口。用同一个普通应用新开连接，核对旧连接和 UI 是否仅未刷新。 | 上游仍未就绪、Clash 连接未重新建立、Windows 选路变化。单凭重启成功无法确定哪一种。 | 若 StarSky 已恢复且 Clash 新请求仍异常，保存正在进行的操作后，从 Clash Verge 托盘退出并重新打开。Agent 协助重启须有授权。 | 复测同一站点、Clash 流量及预期选路。正常换节点且访问无异常时可继续使用。 |
| 一类网站访问失败 | 比较用户选择的国内外公开目标，记录失败层和路径。 | 应用规则、路由、目标站故障、证书或上游错误。 | 仅探测获准目标。改分流规则前备份并获授权。保留有效的安全验证。 | 用同一应用及目标比较改动前后，并记录其它已知正常网站有无变化。 |
| 单一目标发生 CONNECT、TLS 或 HTTP 错误 | 记录第一个可确定的失败阶段、响应码和地址解析方式。用预期正常的公开目标作对照。 | 握手拒绝、远端解析差异、证书问题、目标响应错误。 | 经用户确认后探测特定目标。按实际失败层调整设置或请求服务商支持。 | 在同一路径复测原目标和对照，保持 TLS 验证。 |
| DNS、TCP、UDP 的结果不一致 | DNS 查询、TCP 连接、协议握手及是否收到匹配 UDP 回复分别记录。 | 应用使用不同解析方式、代理仅支持一部分协议或中继丢包。 | 用户同意后选择受控目标进行逐层测试。更改 DNS、适配器、协议模式需单独授权。 | 对每类协议报告观察和未知项。未测试 UDP 时记为 `NOT_TESTED`。 |
| 开机顺序异常 | 比较登录、进程、端口出现和首次成功的时间。 | 计划任务先启动、依赖未就绪、异步恢复、人工刷新。 | 只读检查任务。改变启动项、主动重启或睡眠测试均需获授权。 | 等实际冷启动、登录或唤醒事件，区分自动行为和人工操作。 |
| 刷新订阅覆盖设置 | 对照更新前后配置摘要或哈希及设置来源，确认由谁管理。 | 将变更写到生成文件、合并脚本覆盖、切到另一份配置。 | 默认读取。获授权后通过客户端的原生规则或配置位置实现，并备份初始状态。 | 再刷新后读取实际生效配置并验证同一目标。 |
| 新配置造成断网 | 直接记录被改变的一项、旧值、运行状态及可访问的应急路径。 | 路由指向无监听的入口、配置无效或服务异常。 | 使用已授权的回退。否则先说明恢复命令或界面步骤及影响，取得确认。 | 恢复后核对原配置、监听、原有应用及原网站访问。只恢复文件时保留应用结果待验。 |
| 快照损坏或恢复失败 | 核对文件与已记录的哈希、当前用户和机器、目标环境及输出位置。 | 单个文件损坏、权限或用户变化、数据未完整保存。 | 暂停覆盖。保留最后一份已知可用副本。恢复需要明确授权，先在私有临时目录验证。 | 校验解密和还原结果，再复查所需设置和真正的应用路径。 |
| 权限不足 | 记录哪个只读操作失败、权限范围和仍可完成的检查。 | 非管理员会话、受限事件日志、政策或另一用户的软件。 | 继续普通权限可做的部分。只有必要且范围明确时才请求提升。 | 记录追加证据的实际来源及未能读取的项目。 |

## 发送给供应商之前

基于 [诊断报告模板](../templates/diagnostic-report.md)生成技术支持草稿。保留故障时刻及其时区、客户端版本、Windows 版本、最小可复现的步骤、预期和实际结果、失败层、响应码和对照结果。用文档示例地址或文字标签替换真实网络地址，移除订单、账号、精确私人路径、原始配置和凭据。请求供应商确认故障时刻的协议支持、错误记录以及可用修复。让用户审阅并自行发送。若供应商需要原始资料，明确内容、接收方、敏感范围和安全传输途径。
