# IP 尽调（IP-DUE-DILIGENCE）— `192.0.2.254`

调查时间：2026-11-18。方法：ARIN RDAP/Whois-RWS、RIPEstat（前缀/路由历史/RPKI）、Arisk geofeed、NexIP 公开条款与产品页、Layer3 Intel 公开记录。
**只做公开查询，未登录、未购买、未提交工单。**

> 重要的方法论声明：**没有找到任何公开页面把 `192.0.2.254` 与 NexIP 的库存关联起来。** 下面把"NexIP 的产品承诺"与"这个 IP 的网络归属"分开陈述，不做拼接。

`C11472792` 是**客户记录**，不是 NexIP；公开数据里没有"该客户把地址卖给谁"的信息。

## 2. 路由（BGP，独立数据源）

- RIPEstat：`72.245.192.0/21` **由 AS3257（GTT）宣告**，约 320 个全表 peer；
- 查询的 `/32` **自身未被宣告**，结果对齐到 covering `/21`；
- 路由历史：AS3257 自 2025-08-12 起新增该 `/21` 更具体路由（比再分配记录早一天）；
- **Arisk 自己有 ASN：AS395793**，但**它并不宣告这个 `/21`**（它宣告的是全球若干 `/24`）。

→ 这是理解全部矛盾的关键：**登记主体（Arisk）≠ 路由宣告者（GTT）**。

## 3. 地理（geofeed，自发布）

`ariskisp.com/rfc8805.csv` 中：

```
72.245.192.0/21,US,US-DC,Washington,     ← 包含本 IP
72.245.200.0/21,US,US-DC,Washington,
72.245.128.0/21,US,US-CA,Los Angeles,
```

RFC 8805 明确规定这是**自发布**、**粗粒度**的位置提示（"MAY treat published feed data as a hint only"），不具权威性。注意同一运营商的相邻 `/21` 标 Los Angeles，说明 geofeed 本身按段手写，不是物理位置实测。

## 4. RPKI

- 对 `72.245.192.0/21` 的校验：**`valid`**，匹配的 ROA 是 **AS3257**，`maxLength 24`；
- 同一前缀还存在 **AS2914（NTT）** 的 ROA，对本路由判为 `invalid_asn`。

**`Valid` 只证明**：至少有一个 VRP 与该路由匹配（前缀被覆盖、长度 ≤ maxLength、源 ASN 等于 ROA 的 ASN）。RFC 6811 明确它"只提供有限保护"，防的是**配置错误**而非攻击，也不保证运营者"正统"。

**`Valid` 不证明**：是不是住宅、有没有机房、有没有滥用、geofeed 是否准确、地址是否独享。

同一个 IP 可以同时"黑名单干净"和"被标为高风险匿名出口"——**两者回答的不是同一个问题**。
任何第三方评分都**不能**换算成任何平台的封禁概率。

## 6. 用 NexIP 自己的标准来检验

NexIP 有一篇公开文章专门讲"假住宅 IP"，它给出的**可操作判据**是：

> 原生 IP 由登记它的**宽带运营商自己宣告**，出口位于真实家庭宽带；
> 若**登记为住宅属性却由数据中心/不相关网络 BGP 宣告**，则是广播或租赁网段。

套用到本 IP：**登记主体是 Arisk（ISP），宣告者是 GTT（运营商骨干），Arisk 自己的 AS395793 并不宣告它。**
按 NexIP 自己的判据，这更接近"**运营商地址资源提供的静态 ISP 代理**"，而**不是**"真实家宽线路"。

这不是"假 IP"的指控——它是一种合法且常见的商业形态；只是**"家庭住宅 IP"这个说法缺乏证据**。

## 8. 能真正定性的证据（目前拿不到的）

1. `C11472792` 背后的**再指派合同/服务描述**（ARIN 只给 handle 与地址）；
2. 多地 traceroute/MTR：最后一跳落在** ISP 用户汇聚口**还是**机房边缘**；
3. `/24` 内多 IP 的 **PTR 命名**模式（ISP 用户命名 vs 无/托管命名）；
4. 是否在 **Spamhaus PBL**（"非邮件发射 IP"）等**消费者地址池**名单里；
5. 2–3 家有方法论文档的商业库（IPinfo privacy / MaxMind / IP2Location），记录**厂商+时间+字段**，而不是截图分数；
6. 让 Layer3 解释为何同时标"ISP proxy"与"Hosting"；让 ip.net.coffee 说明住宅标签的判据。

决定性记录（ISP 的用户开通数据）通常不公开，所以合理的最终表述只能是**分级结论**，不能是"100% 住宅"。
