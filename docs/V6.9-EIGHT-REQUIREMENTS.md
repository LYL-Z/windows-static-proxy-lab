## A. 用户原文（逐字保留，不改写）

```text
1.Internet Kill Switch（网络断网开关）：当代理连接意外断开时，立刻切断本机网络，防止真实 IP 意外暴露，避免封号风险。
2\. Clear Flash Cookies & Clear Cookies：彻底清理 Flash 和普通 Cookie 中的历史指纹与缓存，保证每次登录环境都是全新的。
3.Fix DNS leak（修复 DNS 泄漏）：防止浏览器的 DNS 解析请求绕过代理，直接发往本地运营商的服务器，避免真实归属地暴露。
4.Fix IPv6 Leak（修复 IPv6 泄漏）：很多代理默认只接管 IPv4 流量，如果本地开启了 IPv6，真实公网地址会绕过代理直连外网。
5.Fix WebRTC IP leak（修复 WebRTC IP 泄漏）：浏览器通过 WebRTC 协议可实现点对点通信，即使挂上代理，部分网页也能穿透获取真实的本地网络 IP，这是多起因环境异常导致封号的高发原因。
6.保持webRTC DNS IPV6干净
7.starsky、clash verge以及其他一旦有东西异常之后,只要claude桌面端和网页端都看不到中国IP就可以了，最好是可以看到家宽IP或者看不到中国IP，且保证IP不乱跳！同时正常的时候，指向claude的桌面端和网页端的出口IP都为我的家庭IP！
8.starsky和clash verge发生已知的各种状况和问题，最好是能够自动修复，或者我只需最简单的几种方法修复，或者交给一个非常能力不够的ai和agent一句话也能直接修复
```

### 真实范围与边界
1. Windows 系统代理（WinINet）不等于全系统强制代理；默认 Windows Defender Firewall 允许大部分出站连接，需独立评估 Windows Firewall / Windows Filtering Platform 方案。优先使用系统已提供能力，禁止无必要安装不明内核驱动。
2. **不能同时把“静态出口坏了仍需固定出口可用”和“没有独立备用路径”视为已解决**。没有经过实测的同出口备用线路时应上报 UNAVAILABLE，而非更换出口。
3. “Flash Cookies”属于历史浏览器技术：Adobe Flash Player 已结束支持；现代浏览器应核对站点数据、Cookie、缓存与权限。清理不等于浏览器指纹清零，可能造成登出、数据丢失。
4. 第三方 IP/风控评分和单站“绿色”不等于全局安全或任何服务的使用资格。不要把服务账号风控、账号被封后的身份/地域伪装当作验收指标。
5. 不储存或打印实际代理用户名、密码、浏览器会话、令牌、完整个人 IP，也不自动删除历史证据。
6. 不自行改变 StarSky、Clash 系统代理所有权，不在未批准情况下重启客户端、修改防火墙、TUN、DNS、IPv6、杀死进程或安装驱动。
7. 对于无法验证的能力统一返回 NOT_TESTED / UNKNOWN / BLOCKED_PROVIDER，不输出虚假的 PASS。

## D. 分阶段工作与验收门槛

**P0 事实与现场冻结**：读仓库、两个 Draft PR、V6.8 验收，记录生产脚本/配置哈希、HKCU、首跳、核心监听、DNS/IPv6/WebRTC 状态；保留用户已有网络。状态输出包括 SOURCE、TIMESTAMP、METHOD、EVIDENCE、CONFIDENCE。

**P1 离线威胁模型**：枚举 Chrome/桌面测试客户端、WinHTTP/WinINet、系统代理漂移、raw socket、IPv6、UDP/QUIC、WebRTC、DoH、PAC/WPAD、进程启动/退出、StarSky 重连和 Clash 崩溃。逐项给覆盖与未覆盖证据。

**P2 最小隔离原型**：在独立测试配置里研究操作系统级、进程级失败关闭策略，先证明不会破坏 DNS、回环、LAN、国内正常访问；用故障注入验证 TCP/UDP/IPv4/IPv6；不改生产。

**P3 应用与可用性回归**：中性 HTTPS/UDP 端点加实际浏览器/测试客户端，从发送端和接收端核验；同时保留百度、GitHub 等日常访问能力。

**P4 生命周期实验**：重启、睡眠、Wi-Fi 重连、StarSky 节点变化等未经用户授权时保持 NOT_TESTED，不得用模拟替代实机结果。

**P5 独立安全复审**：扫描敏感内容、回滚测试、ACL/DPAPI、事务原子性、故障保护缺口；两轮没有新 HIGH 才能作为候选进行最终验收，不把通过数量等同于覆盖完整。

**P6 提交**：将可公开的文档/代码/合成测试单独提交到 Draft PR，不覆盖生产、不合并；形成能够审计的矩阵和下一步行动。任何生产行为需逐项授权。
